# 참고 자료 — 작업 전 반드시 읽을 것

> `design.md`가 "무엇을 만들 것인가"라면, 이 문서는 **"어떤 재료가 이미 있고, 무엇을 일부러 뺐는가"**를 정리한 것이다.
> 특히 2번 섹션(제외한 설계)은 좋은 의도로 되돌려놓기 쉬운 항목들이므로 주의할 것.

---

## 1. 수업에서 다룬 기능 목록 (구현 명세)

이 과제의 핵심 요건은 **아래 기능들을 응용·조합해 새로운 플레이 경험을 만드는 것**이다.

> 스크립트를 그대로 가져오는 것이 아니라, **아래 기능들의 동작 방식과 구조를 새 프로젝트에서 구현**한다.
> 즉 이 목록은 "이미 있는 것"이 아니라 **"이런 기능들이 있어야 한다"는 명세**로 읽을 것.

각 기능을 이 게임에 맞게 어떻게 응용하는지는 항목마다 표시된 주의사항을 참조할 것.

### Player 조작
| 기능 | 설명 |
|---|---|
| 이동 입력 | Input System으로 방향 입력을 받아 Player의 이동 방향으로 사용 |
| 이동 가능 영역 내 이동 | 입력 방향을 NavMesh Agent에 전달 |
| 이동 방향 바라보기 | Player Model이 이동 방향을 바라보게 함 |

> ⚠️ 이 게임에서는 **이동 입력을 제거**하고 목적지 자동 설정으로 대체한다. NavMesh Agent 이동 자체는 그대로 재사용.

### Camera
| 기능 | 설명 |
|---|---|
| 탑뷰 시점 | Cinemachine Camera로 Player와 주변 전투 공간이 함께 보이는 시점 |
| Player 추적 | Player가 이동해도 탑뷰 구도를 유지하며 따라감 |

### Navigation
| 기능 | 설명 |
|---|---|
| 이동 가능 영역 만들기 | 바닥과 장애물 기준으로 이동 영역 생성 |
| Agent 종류 구분 | Player/Monster의 크기·이동 조건을 구분 |
| 정적 장애물 반영 | 벽·건물 등 고정 장애물을 피해 경로 생성 |
| 동적 장애물 반영 | 이동/생성되는 장애물이 경로를 막게 함 |
| 목적지까지 경로 탐색 | 장애물을 피해 이동 경로 계산 |
| 캐릭터 회피 조정 | 회피 우선순위와 품질 조정 |

> ⚠️ **동적 장애물 반영 기능을 벽에 적용하지 말 것.** 이 게임의 벽은 경로에 영향을 주면 안 된다. (design.md 3.2 참조)

### Animation
| 기능 | 설명 |
|---|---|
| 이동 Animation | 이동 여부에 따라 대기/이동 동작 전환 |
| 공격 Animation | 공격 상태가 되면 공격 동작 재생 |
| 공격 판정 시점 연결 | 공격 Animation의 타격 Frame에서 피해 판정 실행 |
| 사망 Animation | 체력 0이면 사망 동작 재생, 마지막 Frame에서 다음 처리 |

### 공격 대상 탐색 ★ 이 게임의 핵심 재료
| 기능 | 설명 |
|---|---|
| 공통 피해 대상 구분 | Player/Monster가 공통 방식으로 피해를 받을 수 있게 함 |
| Layer로 대상 구분 | 공격 가능 대상을 Layer로 구분 |
| 공격 범위 탐색 | 중심으로부터 정한 범위 안의 대상 탐색 |
| 가장 가까운 대상 선택 | 범위 안 대상 중 최근접 선택 |
| 사망한 대상 제외 | 이미 사망한 대상은 제외 |
| **벽 너머의 대상 제외** | **공격 시작 위치와 조준 위치 사이를 확인하여 벽에 가려진 대상 제외** |

> ★ 맨 아래 "벽 너머의 대상 제외"가 이 게임 전체의 출발점이다. 이 Raycast 로직을 **몬스터 → Player 방향으로 뒤집어** 재사용한다.

### 자동 공격
| 기능 | 설명 |
|---|---|
| 공격 대기시간 | 이전 공격 후 일정 시간이 지나야 다음 공격 실행 |
| 대상 재탐색 대기 | 대상이 없을 때 잠시 기다린 뒤 재탐색 |
| 투사체 발사 | 대상이 있으면 발사 위치에서 투사체를 꺼내 발사 |

> ★ "대상 재탐색 대기"가 중요하다. 벽에 막혀 대상을 찾지 못했을 때 이 로직을 그대로 타면, **"막은 만큼 피격 횟수가 줄어든다"**는 이 게임의 핵심 규칙이 자연스럽게 구현된다.

### 투사체
| 기능 | 설명 |
|---|---|
| 조준 위치 설정 | 대상 중심 대신 별도 지정 위치를 조준 |
| 발사 방향 저장 | 발사 순간의 조준 위치 기준으로 방향을 한 번 계산 |
| 투사체 이동과 회전 | 저장한 방향을 바라보며 일정 속도로 이동 |
| 유지시간 | 충돌하지 않아도 일정 시간 후 반환 |
| 충돌과 피해 전달 | 공격 대상과 충돌 시 공격력 전달 후 사용 종료 |

### Monster 생성 / 행동
| 기능 | 설명 |
|---|---|
| Player 주변 생성 위치 선택 | Player와 일정 거리 떨어진 위치를 생성 후보로 선정 |
| 이동 가능한 생성 위치 확인 | 생성 후보 주변에서 이동 가능한 NavMesh 위치 탐색 |
| Monster 능력치 설정 | 생성 시 최대 체력과 공격력 전달 |
| Player 추적 | Navigation 경로를 따라 Player에게 접근 |
| 공격 시작 판단 | 공격 거리 안 + 벽에 안 가려졌을 때 공격 시작 |
| 공격 범위 판정 | 정한 공격 위치와 거리 안에 Player가 있는지 확인 |
| 공격 각도 판정 | 정면 기준 정한 각도 안에 Player가 있는지 확인 |
| 공격 후 추적 복귀 | 공격 종료 후 다시 추적 |
| 행동 상태 구분 | 추적/공격/사망 상태 구분 |
| Monster 사망 | 체력 0이면 사망 동작 후 반환 |

> ⚠️ 이 게임의 몬스터는 **고정형 타워**다. Player 추적, 공격 후 추적 복귀, 랜덤 생성 위치 선택은 **사용하지 않는다.**
> ⚠️ **공격 각도 판정도 사용하지 않는다.** 원형 사거리만 쓴다.
> ⚠️ Monster 사망 로직도 이번 프로토타입에서는 불필요하다. Player는 몬스터를 공격할 수단이 없다.

### 체력과 사망
| 기능 | 설명 |
|---|---|
| 최대 체력과 현재 체력 | 최대/현재 체력을 구분해 관리 |
| 피해 처리 | 전달받은 피해량만큼 현재 체력 감소 |
| 생존과 사망 판단 | 체력 0 이하면 사망 상태로 변경 |
| Player 행동 중지 | Player 사망 시 이동과 자동 공격 정지 |

### 능력치 / 시작 관리
| 기능 | 설명 |
|---|---|
| Player 능력치 모음 | 최대 체력, 이동속도, 공격 범위, 공격 대기시간, 공격력을 한곳에서 설정 |
| 기능별 능력치 전달 | 시작 시 이동/체력/공격 기능에 필요한 능력치를 각각 전달 |
| Player 준비 | 시작 시 Player 기능들을 사용 가능 상태로 초기화 |
| Monster 배치 | 시작 시 정한 능력치를 전달하여 Monster 배치 |

> `StageManager`를 새로 만들 때 기존 "시작 관리" 로직을 베이스로 확장할 것.

### 전투 정보 표현
| 기능 | 설명 |
|---|---|
| Player 체력 UI | 현재/최대 체력을 화면에 표시 |
| 피격 색상 | 피해를 받으면 Model의 Material을 잠시 변경 후 복구 |
| 피해량 숫자 표시 | 받은 피해량을 피격 위치에 숫자로 표시 |
| 피해 위치를 화면 위치로 변환 | 3D 피격 위치를 UI 좌표로 변환 |
| 피해량 숫자 Animation | 숫자가 나타났다 사라지는 움직임 재생 |

> 이 기능들은 **그대로 재사용**한다. 단, 피격 대상이 Monster가 아니라 **Player**가 된다.

## 2. 검토했으나 의도적으로 제외한 설계

아래는 기획 과정에서 논의했지만 **일부러 넣지 않기로 한 것들**이다.
"이게 있으면 더 좋을 것 같다"는 이유로 임의 추가하지 말 것. 추가하고 싶으면 먼저 물어볼 것.

| 제외한 설계 | 제외 이유 |
|---|---|
| **몬스터 공격 각도 판정 (부채꼴 사거리)** | 유저가 몬스터가 어느 방향을 보는지 매번 파악해야 해서 스테이지 가독성이 떨어짐. 원형이 퍼즐을 더 명확하게 만듦 |
| **Player 직접 이동 조작 / 회피** | 리버스 타워디펜스의 핵심은 "지켜야 할 대상이 스스로 아무것도 못 한다"는 무력함. 회피가 가능하면 실패 원인이 "벽 배치 실수"인지 "조작 실수"인지 흐려짐 |
| **벽의 인접 칸 부분 차폐** | 벽 1개 = 정확히 1칸으로 단순화. 위치 최적화 요소를 넣으면 규칙이 복잡해지고 계산이 불명확해짐 |
| **벽 종류 다양화 / 차등 비용** | 단일 종류·동일 비용으로 통일. 밸런싱 변수를 "재화 총량 대비 필요 벽 개수" 하나로 압축하기 위함 |
| **벽 내구도 / 파괴 가능** | 파괴되지 않는 고정 차단막. 한 번 세우면 끝까지 유지 |
| **실시간 재화 누적 (초당 N 지급)** | 스테이지 시작 시 고정 총량 전액 지급으로 변경. 불확실성 속 자원 배분 판단에 집중하기 위함 |
| **전체 맵 정보 사전 공개** | 정보를 다 보여주면 "미리 계산해서 배치하고 관전하는 게임"이 됨. 시야 제한이 이 게임 재미의 핵심 장치 |
| **스킬 시스템** | 향후 확장으로 분류. 횟수 제한 방식의 "스퍼트(일시 이동속도 증가)" 개념만 정해둠 |
| **별 1~3개 등급제 / 보상** | 향후 확장으로 분류. 프로토타입은 클리어/실패만 판정 |
| **스테이지 3개 이상** | 시연 목적이므로 2개로 압축 (튜토리얼 + 본 시연) |

## 3. 과제 제출 요건 (작업 범위 판단용)

| 항목 | 내용 |
|---|---|
| 제출 기한 | 9월 9일(수) |
| 제출물 | 기획서 PDF + 플레이 영상 MP4 (zip 압축, 100MB 이하) |
| 개발 환경 | Unity 6000.3.9f1 |

### 영상에 담겨야 할 것 (= 반드시 동작해야 하는 것)
- 플레이 **시작부터 종료까지** 전체 흐름
- 기획서에 명시한 기능이 실제로 동작하는 모습
- 새로운 플레이의 **시작 조건 → 동작 과정 → 결과**가 확인 가능해야 함
- 빠른 배속이나 장면 전환 없이 촬영하므로, **한 스테이지가 지나치게 길지 않아야 함**

> 이 요건 때문에 **스테이지 1개당 플레이 시간이 1~2분 내외**가 되도록 경로 길이와 이동 속도를 조정할 것.

### 평가 기준상 중요한 것
- 기능을 **많이** 쓰는 것이 목적이 아니다. 기능의 본질을 응용·조합해 **새로운 경험**을 만드는 것이 목적이다.
- 따라서 안 쓰기로 한 기능(공격 각도 판정 등)을 억지로 끼워 넣을 필요가 없다.

## 4. 이 문서를 읽을 때

- 1번 섹션의 기능 목록은 수업 교안 기준으로 정리한 것이라, 실제 구현 시 이름·구조는 달라도 된다. **동작 방식이 재현되면 된다.**
- 목록에 있는 기능 중 이 게임에 불필요한 것(몬스터 추적, 각도 판정 등)은 구현하지 않는다. 각 섹션의 ⚠️ 표시 참조.
- **2번 섹션(제외한 설계)의 항목을 되돌려 넣지 말 것.** 필요해 보이면 먼저 물어볼 것.
