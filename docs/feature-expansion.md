## 0. 왜 추가하는가

지금 플레이어가 할 수 있는 행동은 "벽 세우기" 하나뿐이다. 캐릭터가 자동으로 걷기 때문에 벽을 다 쓰고 나면 구경만 하게 되고, 이게 밋밋함의 원인이다.

이번 확장의 목표는 **대응 수단과 위협의 짝을 늘리는 것**이다.

| 위협 | 막는 수단 |
|---|---|
| 몬스터 투사체 | 벽 (기존) |
| 낙석 | 타이밍 — 가속 / 정지 / 무적 |
| 가시함정 | 통과 방식 — 가속 / 무적 |
| 빙결 지대(빨라짐) | 판단 여유 확보 — 정지 / 조명탄 |
| 안개(정보 부족) | 조명탄 |

벽으로는 함정을 못 막고, 스킬 횟수도 제한되어 있으니 "어디에 무엇을 쓸지"라는 기존 트레이드오프가 더 넓어진다. 핵심 컨셉("모든 것을 막을 수는 없다")을 흐리지 않는 것이 원칙이다.

## 1. 공통 규칙

- **적용 범위**: 스테이지는 앞으로 **5~10개까지 늘릴 예정**이다. 그래서 모든 기능은 특정 스테이지 전용이 아니라 **어느 스테이지 씬에든 넣고 씬마다 켜고 끌 수 있게** 만든다. 이번 일정에서 실제로 적용하는 곳은 스테이지2이고, 스테이지1(튜토리얼)은 건드리지 않는다
- **씬별 설정 원칙**: 기존 `CurrencyManager.totalCurrency`처럼, 스테이지마다 달라지는 값(스킬 횟수, 함정 위치·주기, 지형 구간)은 전부 그 씬의 인스펙터에서 정한다. 스크립트에 스테이지 번호를 하드코딩하지 않는다
- **프리팹화**: 이번에 만드는 것(스킬 UI, `SkillManager`, 함정 2종, `BiomeZone`, `BiomeManager`, 지형용 Volume)은 전부 프리팹으로 만들어, 새 스테이지에 끌어다 놓기만 하면 동작하게 한다
- **건드리지 않는 것**: 각 컴포넌트의 `visionRadius` 값, 기존 몬스터 수치, 메인 메뉴, 스테이지1 씬
- **재도전(`RetryStage`)** 시 이번에 추가하는 모든 상태(스킬 횟수, 진행 중인 스킬 효과, 함정 주기, 빙결 연출)를 초기 상태로 되돌린다
- **튜토리얼 정지(`timeScale=0`) 중**에는 스킬 사용 불가, 함정 주기와 스킬 지속시간도 멈춘다(scaled time 사용). UI 연출만 `unscaledDeltaTime`
- 피해는 전부 기존 `PlayerHealth.TakeDamage()`를 거친다 → 피해 숫자 팝업, 결과 화면 피격 마커(`damageByTile`)가 자동으로 함께 동작해야 한다
- 새 오브젝트의 레이어는 `Default`. `WallVision`/`AttackTarget`에 올리지 않는다
- 새 머티리얼은 URP 셰이더로 만든다
- 런타임에 공유 머티리얼(`sharedMaterial`) 색을 바꾸지 않는다. Play 모드에서도 에셋 자체가 바뀌어 버린다 → 인스턴스 머티리얼이나 `MaterialPropertyBlock` 사용

## 2. 캐릭터 스킬

### 2-1. 공통 구조

- 신규 `SkillManager`(Managers 아래) — 스킬 4종의 남은 횟수, 사용 가능 여부, 효과 적용/해제를 관리
- 스킬마다 **스테이지별 사용 횟수**가 있고, 벽처럼 다 쓰면 끝이다
- 같은 스킬은 효과가 끝나기 전에 다시 쓸 수 없다(중복 사용 방지)
- 서로 다른 스킬은 동시에 쓸 수 있다(예: 가속 + 무적)
- 캐릭터가 사망했거나 결과 화면이 떠 있으면 사용 불가
- 스킬별 횟수는 씬마다 인스펙터에서 정한다. **횟수 0인 스킬은 버튼 자체를 숨긴다** → 스테이지가 진행되면서 스킬을 하나씩 해금하는 구성이 가능하다
- 버튼이 1~4개 중 몇 개만 보여도 하단 중앙 정렬이 자연스럽게 유지되어야 한다

### 2-2. 입력과 UI

- 화면 **하단 중앙**에 스킬 버튼 4개를 가로로 배치. 우상단은 설정 버튼 자리라 비워둔다
- 버튼 구성: 아이콘 + 남은 횟수 숫자 + 단축키 표시(1~4)
- 키보드 `1`/`2`/`3`/`4`로도 사용(`Keyboard.current`, New Input System)
- 상태 표시
  - 사용 가능: 기본
  - 효과 진행 중: 버튼 위로 지속시간 게이지가 줄어듦
  - 횟수 소진: 어둡게 + 클릭 불가
- 버튼 클릭이 **벽 슬롯 클릭으로 같이 처리되지 않게** `WallPlacementManager`의 레이캐스트 전에 UI 위 클릭인지 확인한다
- 아이콘은 Layer Lab 팩에서 찾아 쓴다. 적당한 게 없으면 목록을 보고하고 결정을 받는다

### 2-3. 스킬 상세

**① 순간 가속**
- 효과: 이동 속도 ×2, 1.5초
- 의도: 위험 구간·가시함정을 빨리 통과한다. 대신 앞에 뭐가 있는지 볼 시간도 줄어든다
- 연출: 캐릭터 뒤 짧은 잔상/트레일
- 속도 배율은 빙결 지대 배율과 곱해진다. **최종 배율 상한 2.5**

**② 무적**
- 효과: 2초 동안 모든 피해 무시(몬스터, 낙석, 가시 전부)
- 투사체는 캐릭터에 맞으면 평소처럼 사라지되 피해만 0
- 연출: 캐릭터를 감싸는 반투명 보호막. 끝나기 0.5초 전부터 깜빡임
- 가장 강한 스킬이라 횟수를 1로 둔다

**③ 정지**
- 효과: 캐릭터가 그 자리에서 3초간 멈춤. 3초가 지나면 자동으로 다시 걷는다
- 몬스터와 함정은 계속 동작한다 → **사거리 안이나 가시 위에서 멈추면 그대로 맞는다**
- 의도: 낙석 타이밍을 흘려보내기, 앞쪽 상황을 보고 벽을 세울 시간 벌기
- 구현: `PlayerAutoMover`에서 `NavMeshAgent.isStopped` 처리. 멈춘 동안 이동 애니메이션(`IsMove`)도 꺼야 한다
- 연출: 캐릭터 머리 위 일시정지 아이콘

**④ 조명탄**
- 효과: 캐릭터의 현재 타일에서 **4타일 앞** 위치에 조명탄을 쏘아, 그 지점 반경 5 안을 3초 동안 밝힌다
- 밝혀진 범위 안의 몬스터, 사거리 표시, 함정이 보이고, 바닥 안개도 캐릭터가 지나간 것과 같은 방식으로 걷힌다
- 4타일 앞이 경로 끝을 넘으면 마지막 타일을 기준으로 한다
- 구현 원칙: **`visionRadius` 값은 바꾸지 않는다.** `FogVisibility` / `AttackRangeIndicator` / `FogOfWarGround`가 지금은 "플레이어 위치 원 하나"만 보고 있는데, 이것을 "시야 원 목록(플레이어 + 활성 조명탄)"을 보도록 확장한다. 조명탄 반경은 조명탄 쪽의 별도 값이다
- 3초가 지난 뒤 몬스터가 다시 숨는지는 기존 컴포넌트의 규칙을 그대로 따른다(새 규칙을 만들지 않음)
- 연출: 조명탄이 포물선으로 날아가 터지고, 착지 지점에 밝은 빛(Point Light 또는 발광 파티클)
- 대안(시간 남으면): 버튼을 누른 뒤 바닥을 클릭해 위치 지정

### 2-4. 튜토리얼

- 스킬이 **처음 등장하는 스테이지**에서 `StageStart` 팝업으로 안내한다. 버튼을 `UIHighlightEffect`로 강조하며 "스킬은 정해진 횟수만 쓸 수 있습니다". 이번에는 스테이지2에 넣는다
- 이후 스테이지에서 새 스킬이 추가로 해금되면, 그 스테이지의 `TutorialManager`에 해당 스킬 안내 팝업을 하나 넣는 방식으로 확장한다(스킬 안내 문구는 스테이지와 상관없이 재사용할 수 있게 한곳에 모아둔다)
- 스킬별 설명은 버튼에 마우스를 올리면 뜨는 짧은 툴팁으로 대체(팝업을 늘리지 않음)

## 3. 함정

### 3-1. 공통

- 벽으로는 막을 수 없다
- **안개 규칙을 따른다**: 함정 오브젝트와 경고 표시에 `FogVisibility`를 붙인다. 시야나 조명탄 범위 안에서만 보인다
- 피해는 `PlayerHealth.TakeDamage()`로 전달 → 무적 중이면 0
- 각 함정은 `IResettable`처럼 재도전 시 초기 상태로 돌아가는 메서드를 가진다

### 3-2. 낙석 함정 (주기형)

- 경로 위 지정 지점에 설치. 아래 주기를 반복한다

| 단계 | 시간 | 내용 |
|---|---|---|
| 대기 | 2.5초 | 아무것도 없음 |
| 경고 | 1.2초 | 바닥에 빨간 원이 작게 나타나 점점 채워짐 |
| 낙하 | 0.3초 | 위에서 바위가 떨어짐 |
| 충돌 | 즉시 | 원 안에 캐릭터가 있으면 피해 15 |
| 잔해 | 0.5초 | 바위가 흔들리며 사라짐 |

- 한 주기 약 4.5초. 함정마다 **시작 지연(offset)** 값을 따로 둬서 여러 개가 동시에 떨어지지 않게 한다
- 충돌 범위 반경 1.5(타일 하나를 거의 덮는 크기)
- 판정은 **충돌 순간 한 번**만 한다. 떨어진 뒤에 들어가면 안 맞는다
- 바위 모델: `Low Poly Nature Bundle`의 바위 프리팹 재사용, 크기는 캐릭터보다 약간 크게
- 경고 원은 사거리 표시처럼 지형에 가려지지 않게 기존 `RangeIndicatorOverlay` 셰이더 방식을 쓴다(색만 빨강)
- 충돌 시 카메라 흔들림은 넣지 않는다(탑다운 카메라 Damping 0 고정 규칙과 충돌할 수 있음)

### 3-3. 가시함정 (상시형)

- 지정한 **연속 타일 2칸** 위에 항상 가시가 솟아 있다
- 캐릭터가 그 위에 있는 동안 **0.25초마다 피해 4**
- 자동 이동이라 피할 수 없다 → 대응은 가속(빨리 통과)이나 무적뿐. 그 위에서 정지를 쓰면 크게 손해
- 기준 계산(속도 3.6, 타일 길이 2): 그냥 지나가면 약 1.1초 → 피해 약 16~20 / 가속 시 약 8 / 무적 시 0
- 비주얼: 타일 위 낮은 가시 여러 개(원뿔 메시 조합), 금속 회색. 길 색과 확실히 구분돼야 한다
- 판정: 트리거 콜라이더 또는 `PathManager`의 현재 타일 인덱스. 코너 근처에서도 정확한 방식으로 선택하고 이유를 보고한다
- 그 타일의 벽 슬롯은 평소처럼 사용 가능

## 4. 빙결 지대

### 4-1. 개념

경로의 일부 구간이 빙결 지대다. 캐릭터가 들어가면 화면 분위기가 차갑게 바뀌고, 미끄러워서 이동이 빨라진다. 나오면 원래대로 돌아간다.

카메라가 완전 탑다운이라 하늘은 거의 안 보인다. 그래서 배경을 통째로 바꾸지 않고 **화면 색감 + 안개 색 + 바닥 색 + 눈 파티클 + 구간 주변 데코**로 전환을 표현한다.

### 4-2. 구조

- 신규 `BiomeZone`: 시작 타일, 끝 타일, 지형 종류(지금은 `Ice` 하나)
- 신규 `BiomeManager`: `PathManager`의 타일 인덱스 변경 이벤트를 받아 진입/이탈을 판단하고 연출과 디버프를 적용

### 4-2-1. 확장 대비 (용암 지대 등)

이번에는 빙결 지대 하나만 구현하지만, **나중에 용암 지대 같은 지형을 코드 수정 없이, 또는 최소한의 추가만으로 늘릴 수 있게** 만든다.

- **지형 설정을 데이터로 분리**: 신규 `BiomeProfile`(ScriptableObject)에 지형 하나의 설정을 모두 담는다
  - 연출: Volume 프로필, 안개 색, 바닥 색, 화면 파티클 프리팹, 전환 시간
  - 효과: 아래 디버프 목록
  - 안내: 첫 진입 튜토리얼 문구
- 빙결 지대는 `Biome_Ice.asset` 하나로 만든다. 용암 지대를 추가할 때는 `Biome_Lava.asset`을 새로 만들어 `BiomeZone`에 연결하는 것만으로 연출이 동작해야 한다
- **디버프를 교체 가능한 단위로 분리**: 디버프 하나를 독립된 클래스로 만들고(예: 공통 베이스 `BiomeEffect` + `OnEnter`/`OnTick`/`OnExit`), `BiomeProfile`이 목록으로 가진다
  - 이번 구현: `SpeedMultiplierEffect`(빙결 미끄러움 ×1.4)
  - 용암 확장 시 예상: `DamageOverTimeEffect`(구간 안에서 주기 피해). **이번에 만들지는 않지만** 이 형태로 추가할 수 있는 구조인지 설계 단계에서 확인한다
- `BiomeManager`에 `if (종류 == Ice)` 같은 지형별 분기를 넣지 않는다. 지형별 차이는 전부 `BiomeProfile`과 `BiomeEffect` 쪽에 둔다
- 지형 종류 enum은 두되(`Ice`, 이후 `Lava` 추가 예정), 동작은 enum이 아니라 프로필이 결정한다
- 한 스테이지에 서로 다른 지형 구간이 여러 개 있어도 동작해야 한다(지형 A 이탈 → 기본 → 지형 B 진입). 구간끼리 붙어 있으면 기본 상태를 거치지 않고 A에서 B로 바로 전환한다
- 속도 배율은 스킬·지형 등 여러 곳에서 곱해지므로, 캐릭터 속도를 한 곳(예: `PlayerAutoMover`의 배율 목록)에서 합산하고 상한 2.5를 적용한다
- `level-design.md`에 "새 지형 구간 추가하는 법" 항목을 짧게 추가한다(프로필 복제 → 값 수정 → `BiomeZone`에 연결 → 타일 범위 지정)

### 4-3. 진입 연출 (1.5초 동안 부드럽게 전환)

- **화면 색감**: 빙결용 URP Volume(Color Adjustments, White Balance — 푸르고 약간 밝게)의 weight를 0→1
- **안개 색**: `FogOfWarGround`의 안개 색을 옅은 하늘색 계열로 전환 *(색만 바꾼다. 반경은 건드리지 않는다)*
- **바닥 색**: 잔디색 → 눈 덮인 흰 푸른색. 인스턴스 머티리얼로 처리(1장 규칙)
- **눈 파티클**: 카메라를 따라다니는 눈 내리는 파티클 시작. 번들의 `Snow.mat`(이미 URP 변환됨) 사용
- 이탈할 때는 같은 방식으로 1.5초 동안 원래대로

### 4-4. 미리 배치하는 것 (런타임 전환 아님)

- 빙결 구간의 길 타일은 얼음색 전용 머티리얼(`M_PathTile_Ice`)로 교체. 기존 `M_PathTile`처럼 안개보다 위에 그려지는 설정 유지
- 구간 주변에 눈 덮인 바위·나무 데코 배치(`Rocks_Snow` 계열 등). 기존 데코와 같은 규칙(경로에서 2.5 이상 떨어뜨림, `FogVisibility` 부착, 레이어 Default)
- 구간 시작 지점에 경계가 보이도록 얼음 조각 몇 개

### 4-5. 디버프 — 미끄러움

- 구간 안에서 이동 속도 ×1.4
- 볼 시간과 벽 세울 시간이 줄어든다 → 정지·조명탄의 가치가 올라간다
- 가속과 곱해질 때 상한 2.5(2-3 참조)
- *(선택, 시간 남으면)* 빙결 지대에서 정지를 쓰면 바로 서지 않고 0.5초 미끄러진 뒤 멈춤

### 4-6. 튜토리얼

- 빙결 지대가 처음 나오는 스테이지에서, 처음 들어갈 때 `TileReached` 팝업 1개: "얼음 위에서는 미끄러져 빨라집니다"
- 구간 시작 1~2타일 전에 뜨게 해서, 팝업이 닫힌 뒤 대응할 여유를 준다

## 5. 스테이지 구성

### 5-1. 5~10스테이지 확장을 위한 사전 정리

새 스테이지를 빠르게 찍어내려면 아래가 먼저 정리돼 있어야 한다.

- ⚠️ **`Fox.prefab`에 `PlayerAutoMover`/`PlayerHealth`가 없다.** 지금은 기존 씬의 인스턴스에만 붙어 있어서, 새 씬에 `Fox.prefab`을 놓으면 두 스크립트가 빠진 채로 나온다. 인스턴스의 값을 확인해 프리팹에 반영(Apply)할지 **먼저 보고하고 승인받는다**
- 스테이지 순서는 각 씬 `StageManager.nextSceneName`으로 연결되어 있다. 새 스테이지를 추가하면 직전 스테이지의 `nextSceneName`을 바꾸고, 마지막 스테이지는 빈 값으로 둔다(마지막 스테이지 = GAME CLEAR). Build Settings 등록도 함께 한다
- `docs/level-design.md`의 "새 스테이지 체크리스트"에 이번 기능(스킬 횟수 설정, 함정 배치, 지형 구간 추가)을 추가한다

### 5-2. 기능 등장 순서 (제안)

스테이지가 늘어나는 만큼 요소를 한 번에 다 주지 않고 조금씩 늘리는 편이 학습 곡선이 부드럽다. 아래는 제안이며, 스테이지 수가 정해지면 확정한다.

| 스테이지 | 새로 등장 | 비고 |
|---|---|---|
| 1 | 벽, 시야 (기존) | 튜토리얼, 변경 없음 |
| 2 | 가속, 무적 / 가시함정 | 이번 일정 적용 대상 |
| 3 | 정지 / 낙석 | |
| 4 | 조명탄 / 빙결 지대 | |
| 5 이후 | 조합, 수치 상승, (용암 지대) | 새 요소 없이 배치로 난이도 조절 |

> 이번 일정에서는 기능 검증과 시연을 위해 **스테이지2에 네 기능을 모두 넣는다.** 스테이지를 늘릴 때 위 순서대로 나눠 옮기면 된다(씬별 설정이라 옮기기 쉬움).

### 5-3. 스테이지2 배치안

> 아래는 **제안**이다. 실제 좌표와 타일을 정하기 전에 후보를 스크린샷과 함께 보고하고 확정받는다.

- 스테이지2는 20타일 ㄴ자 경로(세그먼트 A: 타일 0~9, B: 10~19)
- **가시함정**: 세그먼트 A 후반(타일 6~7 부근). 몬스터 사거리와 살짝 겹쳐 "가속을 쓸까, 벽을 쓸까" 고민이 생기는 위치
- **낙석 2개**: 코너 부근(타일 9~11)에 offset을 다르게 해서 배치
- **빙결 지대**: 세그먼트 B 중반(타일 13~17)
- 도착 직전 2~3타일은 비워서 마지막에 숨 돌릴 구간을 남긴다
- 기존 몬스터 6마리의 위치는 바꾸지 않는다. 겹쳐서 너무 어려우면 함정 위치를 옮긴다

## 6. 초기 수치 모음

| 항목 | 값 |
|---|---|
| 가속 | 속도 ×2 / 1.5초 / **2회** |
| 무적 | 2초 / **1회** |
| 정지 | 3초 / **1회** |
| 조명탄 | 4타일 앞 / 반경 5 / 3초 / **1회** |

| 낙석 | 주기 약 4.5초(대기 2.5·경고 1.2·낙하 0.3·잔해 0.5) / 반경 1.5 / 피해 15 |

| 빙결 지대 | 속도 ×1.4 / 전환 1.5초 |

수치는 인스펙터에서 바로 고칠 수 있게 `[SerializeField]`로 노출한다.

## 7. 작업 순서와 검증 게이트

각 단계가 끝나면 중간 보고하고, 게이트를 통과한 뒤 다음으로 넘어간다.

**E0. 확장 준비 (화요일, E1 전에)**
- 5-1의 `Fox.prefab` 문제 보고 → 승인 후 반영
- 게이트: 빈 씬에 `Fox.prefab`을 놓았을 때 두 스크립트가 붙어 있다 / 기존 두 스테이지 동작에 변화 없음

**E1. 스킬 시스템 (화요일)**
- `SkillManager`, 버튼 UI, 단축키, 가속·무적·정지
- 게이트: 스킬별 효과와 지속시간이 맞다 / 횟수가 줄고 0이면 못 쓴다 / 튜토리얼 정지 중 사용 불가 / 버튼 클릭 시 벽이 같이 세워지지 않는다 / 재도전 시 전부 초기화

**E2. 조명탄 (화요일~수요일)**
- 시야 원 목록 방식으로 세 컴포넌트 확장
- 게이트: 조명탄 범위의 몬스터·사거리·안개가 드러난다 / 각 컴포넌트의 `visionRadius` 값이 작업 전과 같다 / 기존 플레이어 시야 동작에 변화 없음

**E3. 함정 (수요일)**
- 낙석, 가시
- 게이트: 경고 → 낙하 → 충돌 순서와 시간이 맞다 / 원 안에서만 맞는다 / 가시 위에서 틱 피해 / 무적 중 피해 0 / 벽이 함정을 막지 않는다 / 안개 밖에서는 안 보인다 / 결과 화면 피격 마커에 함정 피해가 반영된다

**E4. 빙결 지대 (수요일)**
- `BiomeZone`, `BiomeManager`, Volume·안개 색·바닥 색·파티클 전환, 데코 배치, 미끄러움
- 게이트: 진입과 이탈 시 1.5초 전환 / Play 모드 종료 후 머티리얼 에셋 색이 그대로다 / 속도 배율과 상한이 맞다 / 재도전 시 즉시 원래 색으로
- 확장성 게이트: `Biome_Ice.asset`을 복제해 색만 붉게 바꾼 임시 프로필을 다른 구간에 연결했을 때 **코드 수정 없이** 전환이 동작한다(확인 후 임시 프로필과 구간은 삭제하지 않고 비활성으로 두거나, 삭제 여부를 물어본다) / `BiomeManager`에 지형별 분기가 없다

**E5. 튜토리얼·배치·마무리 (목요일 오전)**
- 스테이지2 팝업 2개, 함정·지대 최종 배치, 직접 플레이해보고 수치 조정

**새 스테이지 확장성 게이트 (E5 안에서)**: 빈 스테이지 씬을 하나 복제해 프리팹만 끌어다 놓고 인스펙터 값만 바꿨을 때, 코드 수정 없이 스킬·함정·지형이 동작하는지 확인한다. 확인용 씬은 Build Settings에 넣지 않는다.

**E6. 빌드 (모든 작업이 끝난 뒤)**
- **E0~E5와 스테이지 추가 작업이 모두 끝나고, 사용자가 빌드를 지시한 뒤에만 진행한다.** 작업 도중에는 빌드하지 않는다
- 빌드 준비: `PlayStats.csv` 경로를 `Application.persistentDataPath`로 변경, 디버그 로그 정리, Build Settings의 스테이지 순서와 각 씬 `nextSceneName` 연결 재확인
- 게이트: 빌드한 실행 파일에서 메인 메뉴 → 첫 스테이지 → 마지막 스테이지 GAME CLEAR → 메뉴 복귀까지 끊김 없이 진행된다 / 실행 파일 환경에서 `PlayStats.csv`가 정상 기록된다

시간이 부족하면 **E4의 데코 배치 → 선택 항목(빙결 정지 미끄러짐) → 조명탄 연출 디테일** 순으로 줄인다.
