# 스테이지 추가 가이드 — 템플릿 씬 + MCP 위임 절차

> 작성일 2026-09-15
> **착수 시점**: `feature-expansion.md`의 E1~E3(스킬 4종, 조명탄, 함정 2종) 완료 후. **E4 빙결 지대는 이번 범위에서 보류**하고 이후 확장으로 남긴다. 이 문서는 `feature-expansion.md`와 별개이며, 그 문서를 수정하지 않는다.
> 역할 분담: **사용자**는 경로(타일)와 몬스터를 배치하고 스테이지 설정값을 정한다. **MCP**는 이 문서의 3장 절차대로 나머지를 채운다.
> 이 문서의 절차는 매번 같은 순서로 수행한다. 절차에 없는 판단이 필요하면 임의로 정하지 말고 보고한다.

---

## 1. 템플릿 씬 (`Assets/Scenes/Stage_Template.unity`)

새 스테이지는 항상 이 씬을 복제해서 시작한다. **Build Settings에는 넣지 않는다.**

### 1-1. 들어가는 것

기존 `Stage2.unity`에서 공통 요소만 가져온다. 값은 기존 스테이지와 동일하게 맞춘다.

| 구분 | 오브젝트 | 비고 |
|---|---|---|
| 매니저 | `StageManager` | `nextSceneName` 비움 |
| | `PathManager` | |
| | `CurrencyManager` | `totalCurrency` = 5 (임시값) |
| | `WallPlacementManager` | `wallLimitEnabled` = true, `wallCost` = 1 |
| | `TutorialManager` | `steps` 비움 |
| | `PlayStatsLogger` | `excludeReactionTimeThisStage` = false |
| | `SkillManager` | 스킬 횟수 전부 0 |
| UI | HUD 캔버스 전체 | `HealthBar`, `CurrencyIcons`, `ProgressBar`, `StageLabel`, `ResultPanel`(+`RetryButton`/`MenuButton`), 스킬 버튼 |
| | `EventSystem` | `InputSystemUIInputModule` 포함 — 없으면 버튼이 안 눌림 |
| 카메라·조명 | `Main Camera`(+Brain), `CM_TopDown`, Directional Light | 기존 값 그대로 |
| 바닥·안개 | `Floor`(NavMeshSurface), `FogGround`(`FogOfWarGround`) | 데코·`GroundBumps` 없음 |
| 캐릭터 | `Player`(`Fox.prefab`) | `PlayerAutoMover`/`PlayerHealth` 포함 확인 (1-4 참조) |
| 경로 예시 | `Path` 아래 `Tile_00`~`Tile_05` | 6칸 ㄴ자 짧은 예시 + 길 비주얼 |
| 몬스터 예시 | `Monster_Basic_Sample`, `Monster_Area_Sample`, `Monster_DPS_Sample` | 각 프리팹 1마리씩, 예시 경로 옆 |

### 1-2. 들어가지 않는 것 (3장 절차에서 생성)

환경 데코, 지형 굴곡(`GroundBumps`), 벽 슬롯, 슬롯 받침대, 도착 포탈, 함정, 튜토리얼 스텝

### 1-3. 기능 관련 원칙

`SkillManager`와 스킬 UI는 템플릿에 넣되 **기본값은 꺼진 상태**(스킬 횟수 0 → 버튼 숨김)로 둔다. 함정은 스테이지마다 다르므로 템플릿에 넣지 않는다. 나중에 빙결 지대 같은 기능이 추가되면 같은 원칙으로 템플릿과 3-7에 반영한다.

### 1-4. 템플릿 만들 때 먼저 확인할 것

- `Fox.prefab` 에셋에는 `PlayerAutoMover`/`PlayerHealth`가 없고 기존 씬 인스턴스에만 붙어 있었다(09-11 기준). 이미 해결됐는지 확인하고, 아니라면 프리팹에 반영(Apply)할지 **보고 후 승인받는다**
- E3에서 만든 함정 프리팹의 **실제 이름·경로·인스펙터 항목**을 확인해 이 문서 4장의 표를 실제 값으로 고친다(이 문서의 이름은 가칭)
- 템플릿 완성 후, 템플릿을 복제해 예시 경로 그대로 3장 절차를 한 번 수행해 시작→클리어까지 동작하는지 확인한다. 확인용 씬은 Build Settings에 넣지 않고, 삭제 여부는 사용자에게 묻는다

## 2. 사용자가 할 일

1. Project 창에서 `Stage_Template.unity` 선택 → `Ctrl+D`로 복제 → 이름을 `Stage3` 식으로 변경
2. 복제한 씬을 열고 예시 타일과 예시 몬스터를 수정하거나 지우고 새로 배치
3. 저장 후 MCP에 요청(5장 양식)

### 배치 규칙

- 타일은 `Path`의 자식으로, **이동 순서대로** 놓는다. 이름은 `Tile_00`, `Tile_01`… (순서가 꼬여도 MCP가 점검 후 보고함)
- 타일 간격은 **2유닛**, 방향은 가로·세로만. 대각선 없음
- 새 타일은 기존 타일을 복제해서 옮기면 편하다. 길 비주얼은 신경 쓰지 않아도 된다(MCP가 다시 만듦)
- 몬스터는 `Chicken` / `Monster_AreaType` / `Monster_DPSType` 프리팹으로 놓는다. **경로 위에 겹치지 않게**
- 바닥이 경로보다 작아도 괜찮다(MCP가 맞춤)
- 캐릭터 위치는 신경 쓰지 않아도 된다(MCP가 첫 타일로 옮김)
- 함정은 요청에 타일 번호로 적거나, 직접 프리팹을 끌어다 놓아도 된다(4장)

## 3. MCP 작업 절차

### 3-0. 시작 전

- Play 모드가 아닌지 확인한다. 실행 중이면 최근 콘솔 로그를 보고 사용자가 플레이 중인지 확인한 뒤 진행한다
- 작업 대상 씬이 열려 있고, 템플릿 자체(`Stage_Template.unity`)가 아닌지 확인한다
- 사용자가 준 설정값(벽 개수, 스킬 횟수, 함정, 튜토리얼)을 정리해 작업 시작 시 한 번 보고한다

### 3-1. 경로 점검

- 타일 순서, 간격(2유닛), 가로·세로 방향만 쓰였는지 확인
- 이름 순서와 실제 이동 순서가 다르거나 간격이 어긋나면 **고치기 전에 보고**한다

### 3-2. 바닥 맞추기

- 경로 전체 범위에 사방 여유 6유닛 이상을 더해 `Floor` 크기와 위치를 조정한다
- `FogGround`도 같은 범위를 덮도록 맞춘다
- NavMesh를 다시 굽는다

### 3-3. 길과 벽 슬롯

- 기존 길 비주얼을 지우고 모든 타일에 `PathTile`을 다시 만든다(Y 0.02, `M_PathTile`)
- 타일마다 좌/우 벽 슬롯 2개: 진행 방향 기준 좌우로 1유닛 이격, Y 0.75, 레이어 `WallSlot`
- 코너 타일은 **나가는 방향 구간이 쓰는 바깥쪽 가장자리**를 사용(대각선 계산 금지)
- 슬롯마다 `SlotPedestal` 배치(`SlotPedestals` 컨테이너 아래, Y 0)

### 3-4. 시작과 도착

- `Player`를 `Tile_00` 위치로 옮기고 다음 타일 방향을 바라보게 한다
- 마지막 타일에 `ArrivalPortal` 배치

### 3-5. 몬스터

- 경로 위에 겹친 몬스터가 있으면 보고한다(임의로 옮기지 않음)
- 몬스터 3개 컴포넌트(`FogVisibility`/`AttackRangeIndicator`)와 `FogOfWarGround`의 `visionRadius`가 **템플릿 값과 같은지만 확인**한다. 숫자를 새로 정하지 않는다. 사용자가 이 스테이지 시야 값을 따로 지정한 경우에만 세 곳을 함께 바꾼다
- 이름을 `Monster_<타입>_<번호>` 형식으로 정리

### 3-6. 지형과 데코

- 이 스테이지 전용 지형 굴곡 메시 `Assets/Mesh/M_GroundBumps_<씬이름>.asset` 생성: 2유닛 격자, flat shading, 경로 중심선 2.2유닛 이내 평탄, 몬스터 주변 반경 2.4 평탄
- `GroundBumps` 오브젝트 배치(콜라이더 없음)
- `Environment` 아래 데코 배치: 기존 18종 프리팹, 경로에서 2.5·몬스터에서 2.5·데코끼리 2.2 이상, Y축 무작위 회전, 레이어 `Default`, `FogVisibility` 부착(씬 시야 값). 개수는 바닥 면적에 비례(30×60 기준 26개)

### 3-7. 스테이지 설정 (요청받은 것만)

- 벽 개수(`CurrencyManager.totalCurrency`)
- 스킬 횟수(`SkillManager`)
- 함정: 4장 규칙대로 배치·점검
- 튜토리얼: 요청받은 스텝만 추가. 새 요소가 처음 나오는 스테이지인데 요청이 없으면 **넣을지 물어본다**

### 3-8. 스테이지 연결

- `StageLabel` 문구를 이 스테이지 번호로 변경
- 이 씬을 Build Settings의 올바른 순서에 등록
- 직전 스테이지의 `nextSceneName`을 이 씬 이름으로 변경하고, 이 씬은 마지막이면 비워둔다. 변경한 다른 씬도 저장

### 3-9. 점검과 보고

아래 목록을 확인하고 결과를 보고한다.

- [ ] `EventSystem` 있음
- [ ] 요청한 스킬만 버튼이 보이고 횟수가 맞음
- [ ] `Player`에 `PlayerAutoMover`/`PlayerHealth` 있음
- [ ] 타일 수 = 벽 슬롯 수 ÷ 2 = 받침대 수 ÷ 2
- [ ] 모든 `visionRadius` 값이 서로 같음(또는 사용자 지정값)
- [ ] 함정 점검(4-4) 통과
- [ ] 경로 전체가 바닥 안에 있음, NavMesh로 첫 타일→마지막 타일 이동 가능
- [ ] 데코·함정 중 `WallVision`/`AttackTarget` 레이어 없음
- [ ] Build Settings 순서와 `nextSceneName` 연결이 맞음
- [ ] Play 모드: 시작 시 콘솔 에러 없음 / 캐릭터가 끝까지 이동 / 클리어 결과 화면 정상
- [ ] 상공 스크린샷 1장(경로·몬스터·함정 전체)
- [ ] 씬 저장(`isDirty=false`), `PROGRESS.md`에 한 줄 기록

## 4. 함정 추가

### 4-1. 함정 종류

| 함정 | 프리팹(가칭) | 위치 기준 | 스테이지마다 바꾸는 값 |
|---|---|---|---|
| 낙석 | `Trap_Rockfall` | 타일 1칸 중심 | 시작 지연(offset), 필요하면 주기·피해 |
| 가시 | `Trap_Spike` | 연속 타일 2칸 | 시작 타일, 필요하면 피해 |

기본 수치는 프리팹 값을 그대로 쓴다. 스테이지에서 바꾼 값은 씬 인스턴스에만 적용하고 프리팹은 수정하지 않는다.

### 4-2. 추가하는 두 가지 방법

**방법 A — 요청에 적기 (기본)**

타일 번호와 필요한 값만 적는다.

```
- 함정: 낙석 타일 8(지연 0), 낙석 타일 10(지연 1.5), 가시 타일 12~13
```

지연을 안 적으면 MCP가 낙석끼리 겹치지 않게 정하고 보고한다.

**방법 B — 직접 배치**

1. `Traps` 오브젝트 아래에 프리팹을 끌어다 놓는다(없으면 새로 만들어도 됨)
2. 대략 원하는 타일 위에 두기만 하면 된다. 정확한 위치는 MCP가 가장 가까운 타일로 맞춘다
3. 요청에 "함정은 직접 배치했음"이라고 적는다

### 4-3. MCP 배치 규칙

- 모든 함정은 `Traps` 컨테이너 아래, 이름은 `Trap_<종류>_<타일번호>` (가시는 시작 타일 번호)
- 낙석: 타일 중심에 맞춘다. 같은 타일에 2개 이상 두지 않는다
- 가시: 연속된 두 타일에 걸치도록 맞춘다. **코너 타일에 걸치면 모양이 어긋날 수 있으니 보고**한다
- 첫 타일(`Tile_00`)과 마지막 타일에는 두지 않는다. 요청이 그렇게 왔으면 보고
- 낙석이 여러 개면 시작 지연을 서로 다르게 해 동시에 떨어지지 않게 한다
- 레이어 `Default`, `FogVisibility` 부착(씬 시야 값)
- 함정 주변 반경 2.4는 지형 굴곡을 평탄하게 한다(3-6 메시 생성 시 반영)
- 함정 주변 데코는 2.5 이상 떨어뜨린다

### 4-4. 함정 점검

- [ ] 모든 함정이 경로 타일 위에 있음(타일 번호 목록으로 보고)
- [ ] 같은 타일에 함정 중복 없음
- [ ] 낙석 시작 지연이 서로 다름
- [ ] **대응 수단 확인**: 가시가 있는데 가속·무적 횟수가 둘 다 0이면 경고. 낙석이 있는데 가속·정지·무적이 모두 0이면 경고 (막을 방법이 없는 함정이 됨)
- [ ] 함정이 처음 등장하는 스테이지인데 튜토리얼 요청이 없으면 질문
- [ ] Play 모드에서 함정마다 한 번 이상 동작 확인, 무적 중 피해 0 확인
- [ ] 상공 스크린샷에 함정 위치 표시

### 4-5. 새로운 함정 종류가 생기면

4-1 표에 한 줄 추가하고, 위치 기준(1칸/여러 칸)과 대응 수단(4-4)만 정하면 같은 절차로 쓸 수 있다.

## 5. 요청 양식 (복사해서 사용)

```
Stage3.unity에 타일과 몬스터 배치해뒀어.
docs/stage-add-guide.md 3장 절차대로 나머지 채워줘.

- 벽 개수: 6
- 스킬: 가속 1, 정지 1 (나머지 0)
- 함정: 낙석 타일 8, 가시 타일 12~13  (또는 "직접 배치했음")
- 튜토리얼: 낙석 첫 등장 안내 넣어줘
- 시야: 기본값

끝나면 3-9, 4-4 점검 결과랑 스크린샷으로 보고해줘.
```
