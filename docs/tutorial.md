# 튜토리얼 상세 기획

> `design.md` 6장(스테이지 구성)의 하위 문서.
> 스테이지 1·2에서 플레이어에게 무엇을, 언제, 어떻게 알려줄지 정리한다.

---

## 1. 설계 원칙

**① 겪게 한 뒤 설명한다**
"벽이 공격을 막습니다"라고 먼저 읽히면 그냥 지나가는 정보가 된다.
한 번 맞아보고 → 왜 맞았는지 알려주고 → 막아보게 하는 순서가 훨씬 강하게 남는다.

**② 한 번에 하나만 알려준다**
일시정지 한 번에 개념 하나. 두 개를 붙이면 둘 다 흐려진다.

**③ 읽는 시간을 뺏지 않는다**
한 화면에 두 줄 이내. 길어질 것 같으면 나눠서 두 번 멈춘다.

**④ 뒤로 갈수록 개입을 줄인다**
스테이지 1은 손을 잡아주고, 스테이지 2는 거의 놓아준다.
마지막 개념("전부 막을 수 없다")은 설명 대신 **재화를 부족하게 주는 것으로** 전달한다.

**⑤ 조작 가능한 것을 먼저 알린다**
이 게임은 캐릭터를 움직일 수 없다. 이걸 모르면 플레이어는 초반을 이동 키 누르는 데 쓴다.

---

## 2. 학습 순서

아래 순서를 지킨다. 각 항목은 앞 항목을 알아야 이해된다.

| 순서 | 알려줄 것 | 왜 이 순서인가 |
|---|---|---|
| 1 | **캐릭터는 자동으로 이동한다. 조작할 수 없다.** | 이걸 모르면 나머지 설명이 안 들어온다 |
| 2 | **몬스터가 나를 공격한다.** 주황 원이 사거리다 | 위협의 정체와 범위를 먼저 인지 |
| 3 | **벽을 세우면 공격을 막는다** (★ 핵심) | 위협을 알아야 해법이 의미를 가진다 |
| 4 | **벽은 개수가 정해져 있다** | 해법을 알아야 "아껴야 한다"가 와닿는다 |
| 5 | **지나간 곳에는 세울 수 없다** | 실제로 막혀보기 전에 알려줘야 억울하지 않다 |
| 6 | **멀리 있는 위협은 보이지 않는다** | 앞의 규칙을 다 알아야 "미리 못 본다"가 긴장이 된다 |
| 7 | **전부 막을 수는 없다. 무엇을 포기할지 골라라** | 이 게임의 결론. 설명이 아니라 체험으로 |

## 3. 스테이지 1 — 튜토리얼 시퀀스

경로 20칸 기준. 타일 인덱스는 실제 스테이지 조립 시 조정한다.

### 시작 직전 — 일시정지 ①
> **알려줄 것 (순서 1)**

- 화면: 캐릭터만 밝게, 나머지는 어둡게
- 문구: `이 여우는 스스로 길을 걸어갑니다. 당신은 움직일 수 없습니다.`
- 진행: 클릭하면 이동 시작

### 첫 몬스터가 시야에 들어온 순간 — 일시정지 ②
> **알려줄 것 (순서 2)**

- 트리거: `FogVisibility`가 첫 몬스터를 최초로 공개하는 시점
- 화면: 해당 몬스터와 주황 사거리 원을 강조, 나머지 어둡게
- 문구: `저 닭은 원 안에 들어온 대상을 공격합니다.`
- 진행: 클릭하면 재개 — **여기서는 아직 벽을 알려주지 않는다**

### 첫 피격 직후 — 일시정지 ③
> **알려줄 것 (순서 3, ★ 핵심)**

- 트리거: 플레이어가 처음으로 피해를 입은 직후
- 화면: 줄어든 체력 UI 강조 → 이어서 앞쪽 벽 슬롯 하나만 밝게
- 문구 1: `공격을 맞았습니다.`
- 문구 2: `길 옆에 벽을 세우면 공격을 막을 수 있습니다.`
- 진행: **해당 슬롯을 클릭해야만 재개** (강제 유도)
  - 이때 다른 슬롯은 클릭 불가 상태로 잠근다
- 재개 후: 투사체가 그 벽에 맞고 사라지는 장면을 반드시 보게 배치

> ⚠️ 이 구간이 튜토리얼 전체에서 가장 중요하다.
> "맞았다 → 벽을 세웠다 → 안 맞는다"가 한 흐름으로 이어져야 한다.

### 벽을 처음 세운 직후 — 일시정지 ④
> **알려줄 것 (순서 4)**

- 화면: 남은 벽 개수 UI 강조
- 문구: `벽은 정해진 개수만 세울 수 있습니다. 남은 개수를 확인하세요.`
- 진행: 클릭하면 재개

### 두 번째 몬스터 구간 진입 전 — 일시정지 ⑤
> **알려줄 것 (순서 5)**

- 화면: 이미 지나온 슬롯들을 회색으로, 앞쪽 슬롯들을 밝게 표시
- 문구: `이미 지나온 자리에는 벽을 세울 수 없습니다.`
- 진행: 클릭하면 재개 — 이후부터는 자유 플레이

### 스테이지 1 클리어 후
- 결과 화면에 남은 체력·사용한 벽 개수 표시
- 문구: `더 적은 벽으로 더 적게 맞을 수 있을까요?`
  - 재도전 동기를 여기서 심는다

## 4. 스테이지 2 — 최소 개입

### 시작 직전 — 일시정지 ⑥
> **알려줄 것 (순서 6)**

- 문구: `이제 시야가 좁아집니다. 멀리 있는 위협은 가까이 가야 보입니다.`
- 진행: 클릭하면 시작

### 그 이후 — 일시정지 없음
> **순서 7은 설명하지 않는다.**

"전부 막을 수 없다"는 **재화를 부족하게 주는 것으로** 전달한다.
`design.md` 4장 밸런스 공식대로 재화를 산정하면, 플레이어는 자연스럽게
"어디를 포기할지" 고민하게 된다. 여기서 문구로 설명하면 오히려 김이 샌다.

단, 첫 실패 시에만 게임 오버 화면에 한 줄 덧붙인다.
- `모든 공격을 막을 수는 없습니다. 어디를 포기할지 골라보세요.`

## 5. 연출 목록

### 5.1 일시정지 진입·해제

| 구분 | 연출 |
|---|---|
| 진입 | 0.2초에 걸쳐 `Time.timeScale`을 1 → 0으로 낮춤 (뚝 끊기지 않게) |
| 진입 | 화면 채도를 살짝 낮추고 반투명 검정 오버레이를 페이드인 |
| 진입 | **강조 대상만 오버레이 위로** 올려 원래 밝기 유지 |
| 문구 | 화면 하단 중앙, 두 줄 이내. 한 글자씩 빠르게 타이핑되듯 출력 |
| 대기 | 우하단 `클릭하여 계속`이 천천히 깜빡임 |
| 해제 | 오버레이 페이드아웃 후 `timeScale` 복귀 |

> ⚠️ `timeScale = 0` 상태에서는 `deltaTime`이 0이므로, 모든 튜토리얼 연출은
> **`Time.unscaledDeltaTime`** 으로 구동해야 한다. 이걸 놓치면 화면이 멈춘 채로 아무것도 안 움직인다.

### 5.2 UI 강조 — 원 + 화살표

남은 벽 개수, 체력 같은 **화면 UI**를 가리킬 때 쓴다.

- 대상 주변에 원(또는 둥근 사각형) 테두리가 **시계 방향으로 그려지듯** 나타남
- 원은 처음에 크게 시작해 대상 크기로 **수축**하며 자리를 잡음 — 시선을 확실히 끌어당김
- 화면 안쪽에서 화살표가 대상을 가리키며 위아래(또는 좌우)로 살짝 튕기듯 반복
- 대상 UI 자체도 1.15배 정도 확대

> 원이 수축하는 연출 하나만으로 "여기를 봐라"가 충분히 전달된다.
> 반짝임·색 변화까지 겹치면 오히려 산만해진다.

### 5.3 카메라 줌인 — 몬스터 소개 전용

**일시정지 ②에서만** 사용한다. 매번 줌인하면 흐름이 늘어진다.

- Cinemachine **튜토리얼 전용 가상 카메라**를 하나 더 두고 Priority를 올려 전환
  - Follow 대상: 해당 몬스터
  - FOV: 기본 48 → **28** 정도로 좁힘
- 설명이 끝나면 Priority를 내려 `CM_TopDown`으로 복귀
- 줌인이 끝난 뒤 사거리 원을 **한 번 크게 퍼졌다 제자리로** 수축시켜 범위를 각인

> ⚠️ `CM_TopDown`의 Damping은 안개 경계 때문에 (0,0,0)으로 고정되어 있다.
> **튜토리얼 카메라는 별개 오브젝트이므로 Damping을 줘도 된다** — 오히려 있어야 부드럽다.
> 복귀 시 안개는 캐릭터 위치 기준이라 영향받지 않는다.

### 5.4 월드 오브젝트 강조

| 대상 | 방식 |
|---|---|
| 몬스터 | 발밑에 원형 마커, 사거리 원을 굵게 + 색 진하게 |
| 벽 슬롯 | 빛나는 외곽선 + 위아래로 움직이는 3D 화살표 |
| 잠긴 슬롯 (⑤) | 회색으로 낮추고, 배치 가능한 슬롯만 원래 색 유지 |
| 시야 경계 (⑥) | 캐릭터 중심 원을 한 번 크게 그렸다가 `visionRadius` 크기로 수축 |

### 5.5 상시 피드백 연출

튜토리얼 밖에서도 항상 적용한다. **이쪽이 튜토리얼 문구보다 오래 남는다.**

| 상황 | 연출 |
|---|---|
| 투사체가 벽에 막힘 | 부딪히는 순간 짧은 파티클 + 벽이 살짝 흔들림 |
| 플레이어 피격 | 화면 가장자리 붉은 플래시 (기존 피격 색상과 별개) |
| 벽 배치 성공 | 슬롯에서 벽이 솟아오르는 짧은 애니메이션 + 짧은 화면 진동 |
| 재화 부족 상태로 클릭 | 남은 벽 UI가 붉게 흔들림 |
| 배치 불가 슬롯 클릭 | 슬롯이 붉게 한 번 점멸 |
| 새 몬스터가 시야 진입 | 사거리 원이 한 번 크게 퍼졌다 제자리로 |
| 마우스를 슬롯 위에 올림 | 반투명 벽 미리보기 표시 |
| 남은 벽이 0이 됨 | 남은 벽 UI 색이 붉게 고정 |

> **"새 몬스터 시야 진입"** 은 시야가 좁은 스테이지 2에서 특히 중요하다.
> 갑자기 나타난 위협을 놓치면 검증 의도 ②(반응 시간)가 측정 자체가 안 된다.

> **"슬롯 위 반투명 미리보기"** 는 튜토리얼 문구를 하나 줄여주는 효과가 있다.
> 어디에 세워지는지 보여주면 굳이 설명할 필요가 없다.

### 5.6 첫 벽 차단 순간 (1회성)

일시정지 ③ 직후, 처음으로 투사체가 벽에 막히는 그 순간에만.

- 투사체가 벽에 닿기 직전 **0.3초 슬로우모션** (`timeScale` 0.2)
- 충돌 순간 파티클을 평소보다 크게
- 이후 정상 속도 복귀

> "막았다"는 감각을 확실히 각인시키는 용도. **반복하면 늘어지므로 1회만.**

### 5.7 결과 화면

| 구분 | 연출 |
|---|---|
| 클리어 | 남은 체력·사용한 벽 개수를 하나씩 순차적으로 카운트업 |
| 클리어 | 사용한 벽이 적을수록 강조 색을 다르게 (재도전 동기) |
| 실패 | 화면이 천천히 회색으로 물들며 정지 |
| 실패 | 어디서 얼마나 맞았는지 경로 위에 간단히 표시 — **어디를 놓쳤는지 보여준다** |

> 실패 화면의 마지막 항목이 이 게임의 학습 루프를 완성한다.
> "왜 죽었는지" 모르면 재도전해도 같은 실수를 반복한다.

## 6. 시스템 요구사항

Claude Code가 구현할 때 참고할 것.

### TutorialManager
```
TutorialManager
  - 튜토리얼 단계 목록을 인스펙터에서 구성 (ScriptableObject 또는 배열)
  - 각 단계: 트리거 조건 / 문구 / 강조 대상 / 강조 방식 / 진행 조건
  - Time.timeScale 제어 (0 정지 / 1 재개, 0.2초 보간)
  - 스테이지별로 켜고 끌 수 있어야 함 (스테이지 2는 ⑥ 하나만)
```

### 강조 방식 종류
인스펙터에서 단계마다 고를 수 있게 한다.

| 값 | 동작 |
|---|---|
| `UIHighlight` | 화면 UI에 원 + 화살표 (5.2) |
| `WorldHighlight` | 월드 오브젝트 강조 (5.4) |
| `CameraZoom` | 튜토리얼 카메라로 줌인 (5.3) — ②에서만 사용 |
| `None` | 문구만 표시 |

### 단계별 연출 배정

| 일시정지 | 강조 방식 | 대상 |
|---|---|---|
| ① 자동 이동 | `WorldHighlight` | 캐릭터 + 진행 방향 화살표 |
| ② 몬스터 소개 | `CameraZoom` | 첫 몬스터 + 사거리 원 |
| ③ 벽 배치 ★ | `UIHighlight` → `WorldHighlight` | 체력 UI → 지정 슬롯 |
| ④ 벽 개수 | `UIHighlight` | 남은 벽 UI |
| ⑤ 지나간 슬롯 | `WorldHighlight` | 잠긴 슬롯 / 가능한 슬롯 대비 |
| ⑥ 시야 제한 | `WorldHighlight` | 시야 경계 원 |

> ③은 두 단계를 연달아 쓴다. 체력이 줄어든 걸 먼저 보여주고, 그다음 슬롯으로 시선을 옮긴다.

### 트리거 종류
| 트리거 | 연결 대상 |
|---|---|
| 스테이지 시작 | `StageManager` |
| 몬스터 최초 공개 | `FogVisibility`의 공개 이벤트 |
| 첫 피격 | `PlayerHealth`의 피해 이벤트 |
| 첫 벽 배치 | `WallPlacementManager`의 배치 이벤트 |
| 특정 타일 도달 | `PathManager`의 현재 타일 인덱스 |

> 기존 스크립트에 튜토리얼 코드를 직접 넣지 말 것.
> 이벤트를 구독하는 방식으로 `TutorialManager`가 혼자 처리한다.

### 진행 조건
- `클릭` — 아무 곳이나 클릭하면 재개
- `특정 슬롯 클릭` — 지정한 슬롯에 벽을 세워야만 재개 (일시정지 ③)
  - 이때 다른 슬롯은 일시적으로 잠금

### 주의
- `Time.timeScale = 0` 상태에서도 UI 클릭과 벽 배치 입력은 받아야 한다
  (`Update`에서 입력을 처리하되 게임 로직만 멈추는 구조)
- **모든 튜토리얼 연출은 `Time.unscaledDeltaTime`으로 구동한다.** `deltaTime`을 쓰면 정지 중에 아무것도 움직이지 않는다
- 튜토리얼 문구는 한글 폰트(맑은 고딕) 사용 — 기본 Arial은 한글이 깨진다
- 튜토리얼 카메라는 `CM_TopDown`과 **별개 오브젝트**로 만든다. `CM_TopDown`의 Damping (0,0,0) 설정은 건드리지 말 것 (안개 경계가 어긋난다)
- 상시 피드백 연출(5.5)은 `TutorialManager`가 아니라 **각 기능 스크립트에서 직접** 처리한다. 튜토리얼이 꺼진 스테이지에서도 동작해야 한다

## 7. 검증 로그와의 관계

> `design.md` 10장 검증 의도 ②(반응 시간 측정)와 충돌할 수 있다.

일시정지 중에는 시간이 멈추므로, 반응 시간을 `Time.time`으로 재면
튜토리얼 정지 시간이 섞이지 않는다(`timeScale = 0`이면 `Time.time`도 멈춤).
다만 안전하게 하려면:

- **스테이지 1은 반응 시간 측정 대상에서 제외**한다 (튜토리얼 개입이 많아 데이터가 오염됨)
- 반응 시간은 **스테이지 2 데이터만** 사용
- 스테이지 1에서는 재화 밸런스(검증 의도 ①)만 측정
