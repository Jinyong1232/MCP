# UI 기획

> 현재 UI는 텍스트만 있어 게임처럼 보이지 않는다. 이 문서는 무엇을 어떻게 보여줄지 정한다.
> **GUI 에셋을 적극 활용하는 것이 최우선.** 도형을 직접 조합해 만드는 것은 에셋으로 안 되는 경우에만.

---

## 1. 원칙

**① 숫자를 읽게 하지 않는다**
`체력: 90/100`은 읽고 계산해야 한다. 바로 보고 알 수 있는 형태(바, 아이콘 슬롯)로 바꾼다.
숫자는 **보조**로만 함께 표시한다.

**② 줄어드는 것은 줄어드는 게 보여야 한다**
남은 벽, 체력, 남은 거리 — 이 게임의 긴장감은 전부 "줄어드는 자원"에서 나온다.
숫자가 바뀌는 것보다 **칸이 비고 바가 짧아지는 것**이 훨씬 강하게 전달된다.

**③ 에셋을 먼저 쓴다**
패널·버튼·바·아이콘은 가져온 GUI 에셋에서 찾아 쓴다.
에셋에 없는 것만 Unity 기본 `Image`로 대체하고, 그 사실을 기록에 남긴다.

**④ 화면을 가리지 않는다**
HUD는 가장자리에 붙인다. 경로와 몬스터 사거리 원이 가려지면 플레이가 불가능해진다.

---

## 2. 에셋 준비 가이드

사용자가 GUI 에셋을 고를 때 아래가 들어있는지 확인하면 좋다.

| 종류 | 용도 |
|---|---|
| 패널 / 프레임 (9-slice) | HUD 배경, 결과 창, 튜토리얼 말풍선 |
| 버튼 (일반/호버/눌림 3종) | 재도전, 다음 스테이지, 시작 |
| 게이지 바 (프레임 + 채움 2장) | 체력, 진행도 |
| 아이콘 | 하트(체력), 벽, 깃발(도착), 별(등급, 향후) |
| 한글 지원 폰트 | **없으면 따로 구해야 함** (아래 5장 참조) |

> 대부분의 GUI 팩에는 한글 폰트가 없다. 폰트는 별도로 준비해야 한다.

## 3. 인게임 HUD

### 배치

| 위치 | 요소 |
|---|---|
| 좌상단 | 체력 바 |
| 좌상단 (체력 아래) | 남은 벽 |
| 상단 중앙 | 진행도 바 |
| 우상단 | 스테이지 표시 |

### 3-1. 체력 바

- 하트 아이콘 + 게이지 바 + 현재 수치
- 바는 **프레임 이미지 위에 채움 이미지**를 겹치고, 채움 쪽 `Image Type`을 `Filled`(Horizontal)로
- 피해를 입으면 `fillAmount`가 **0.2초에 걸쳐 줄어들도록** 보간 (뚝 끊기면 싸구려로 보인다)
- 체력 구간별 색 변화
  - 60% 초과: 기본색
  - 30~60%: 주황 계열
  - 30% 이하: 빨강 + 바가 천천히 맥박치듯 깜빡임
- 숫자는 바 오른쪽에 작게 (`90` 정도, `/100`은 생략)

### 3-2. 남은 벽

- **아이콘 슬롯 방식.** 총 개수만큼 벽 아이콘을 나열하고, 쓴 만큼 어둡게 처리
- 예: 6개 중 2개 사용 → 밝은 아이콘 4개 + 어두운 아이콘 2개
- 총 개수가 10개를 넘어가면 슬롯이 길어지므로, 그때는 `아이콘 + 숫자` 방식으로 전환
- 벽을 배치하면 해당 슬롯이 **어두워지는 짧은 애니메이션**
- 0개가 되면 전체가 붉게 고정

### 3-3. 진행도 바

- 출발지 → 도착지 사이에서 플레이어가 어디쯤인지
- 현재 위치에 캐릭터 아이콘(또는 점) 표시, 끝에 깃발 아이콘
- `PathManager`의 현재 타일 인덱스 ÷ 전체 타일 수로 계산
- **얇게.** 화면 상단을 많이 차지하면 안 된다

> 지금 없는 정보지만 꼭 필요하다. "얼마나 남았는지" 모르면 재화를 아낄지 쓸지 판단할 수 없다.

### 3-4. 스테이지 표시

- `Stage 1` 정도의 짧은 텍스트. 작게, 눈에 띄지 않게
- 패널 배경 없이 텍스트만으로 충분

## 4. 결과 화면

### 4-1. 클리어

- 화면 중앙에 패널, 뒤는 어둡게
- 표시 항목
  - `Stage Clear` 타이틀
  - 남은 체력 (바 + 숫자)
  - 사용한 벽 개수 (`6개 중 4개 사용`)
  - 클리어 시간 (선택)
- 항목은 **위에서부터 하나씩 순차적으로** 나타나게 (0.2초 간격)
- 숫자는 0에서 실제 값까지 카운트업
- 버튼: `다시 하기` / `다음 스테이지`

> 사용한 벽이 적을수록 강조 색을 다르게 하면 재도전 동기가 생긴다.
> 별 등급제는 향후 확장이므로 지금은 넣지 않는다. 다만 **자리는 비워둔다.**

### 4-2. 실패

- 화면이 천천히 회색으로 물들며 정지
- 표시 항목
  - `Game Over` 타이틀
  - 어디까지 갔는지 (진행도 바를 그대로 보여줌)
  - 가장 피해를 많이 입은 구간 표시 (가능하면)
- 버튼: `다시 하기`

> "왜 죽었는지" 모르면 재도전해도 같은 실수를 반복한다.
> 진행도 바에 피격 지점을 점으로 찍어주는 것만으로도 충분하다.

## 5. 공통 규칙

### 폰트

**가장 먼저 할 것.** 기본 폰트만 바꿔도 체감이 절반은 달라진다.

- 무료 한글 폰트를 받아 TMP Font Asset으로 변환
  (`Window > TextMeshPro > Font Asset Creator`)
- 한글은 글자 수가 많으므로 **Dynamic** 방식 권장. Static으로 만들면 아틀라스가 터진다
- 타이틀용 / 본문용 2종이면 충분
- 아웃라인이나 그림자를 살짝 주면 배경 위에서 읽기 쉬워진다

### Canvas 설정

- `Canvas Scaler` → `Scale With Screen Size`
- Reference Resolution: `1920 x 1080`
- Match: `0.5` (가로세로 균형)

> 이걸 안 하면 해상도가 바뀔 때 UI가 깨진다. 빌드에서 특히 문제가 된다.

### 앵커

- 좌상단 요소는 앵커를 **좌상단에 고정**, 우상단 요소는 우상단에 고정
- 중앙 정렬 앵커를 쓰면 해상도가 바뀔 때 위치가 틀어진다

### 9-slice

- 패널·버튼 이미지는 `Sprite Editor`에서 `Border` 값을 설정하고
  `Image` 컴포넌트의 `Image Type`을 `Sliced`로
- 이걸 안 하면 크기를 늘렸을 때 테두리가 뭉개진다

### 색

기존 게임 톤(황토색 경로, 여우·닭)과 맞는 따뜻한 색 계열을 유지한다.
에셋 팩의 기본 색이 톤과 안 맞으면 `Image`의 `Color`로 틴트를 준다.

## 6. 작업 절차

> 이 순서대로. 한 단계씩 보고하고 확인받은 뒤 다음으로.

| 순서 | 작업 |
|---|---|
| U1 | 폰트 교체 (TMP Font Asset 생성 + 기존 텍스트 전부 적용) |
| U2 | Canvas Scaler / 앵커 정리 |
| U3 | 에셋 스프라이트 임포트 + 9-slice Border 설정 |
| U4 | 인게임 HUD 재구성 (체력 바 → 남은 벽 → 진행도 순) |
| U5 | 결과 화면 (클리어 / 실패) |
| U6 | 애니메이션 (바 보간, 카운트업, 슬롯 전환) |

### 주의

- 기존 UI 오브젝트를 **삭제하지 말고** 교체할 것. `PlayerHealthUI` 등 스크립트가 참조하고 있다
- 참조가 끊기면 `NullReferenceException`이 난다. 교체 후 Inspector에서 연결 확인
- 튜토리얼 오버레이는 `tutorial.md` 5장에 이미 기획되어 있다. 여기서 중복 설계하지 말 것
- 에셋에 없어서 기본 `Image`로 대체한 것이 있으면 `PROGRESS.md`에 남길 것

## 7. 체크리스트

- [ ] 한글이 깨지지 않는가 (전체 텍스트 확인)
- [ ] 해상도를 바꿔도 UI가 제자리에 있는가 (Game 뷰에서 16:9 / 4:3 / 21:9 확인)
- [ ] HUD가 경로나 몬스터 사거리 원을 가리지 않는가
- [ ] 체력 바가 피해량과 맞게 줄어드는가
- [ ] 벽 슬롯이 배치할 때마다 하나씩 어두워지는가
- [ ] 진행도 바가 도착 시 끝까지 차는가
- [ ] 결과 화면 버튼이 실제로 동작하는가 (`EventSystem` 확인)
- [ ] 두 스테이지 모두에서 확인했는가
